-------------
[DONE]         Fully implemented and verified.
[IN PROGRESS]  Work has started but completion definition is not satisfied.

--------------------------
READ CURRENT STATE
→ FIND FIRST UNFINISHED ITEM
→ IMPLEMENT
→ TEST
→ FIX
→ RETEST
→ UPDATE STATUS
→ COMMIT STABLE WORK
→ IMMEDIATELY START NEXT ITEM

Do NOT stop because a module, migration, commit, or checkpoint finished.
Do NOT stop because the session feels long.
Do NOT ask routine confirmations.
Do NOT reorder the implementation queue merely because another module is smaller, easier, or
faster to finish. Work the FIRST unfinished required module in the ordered queue unless a real
technical dependency requires a temporary detour. If you make such a detour, return immediately
to the skipped module as soon as the dependency is satisfied.
If one external integration is blocked, mark only that item [BLOCKED] and continue everything
else. Stop only when all implementable items are [DONE], or every remaining item is genuinely
[BLOCKED].

A clean checkpoint is never a reason to return control to the user. After each stable commit,
read the queue again and immediately begin the next unfinished item.
